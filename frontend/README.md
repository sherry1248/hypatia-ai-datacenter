# Hypatia LEO 운영 콘솔

기존 Hypatia 시뮬레이션 CSV를 CesiumJS 3D 글로브에 표시하는 React 기반 운영 콘솔입니다. 위성·지상국 이동과 함께 정상/단일 ISL 장애/다중 ISL 장애 시나리오의 활성 링크, 선택 경로, 장애 링크, 배치 및 도달 가능 상태를 시각화합니다. 시나리오 선택은 로컬 메트릭 서버 제어 API와 동기화됩니다.

## 사전 준비

- Node.js 18 이상
- npm
- 저장소의 `satgenpy/demo_data/node_positions.csv`

## 실행

### 접속 URL

- Cesium 운영 콘솔: <http://localhost:5173>
- Grafana: <http://localhost:3000>
- Prometheus targets: <http://localhost:9090/targets>

### 권장 시작 순서

1. Prometheus를 시작하고 targets 화면에서 수집 대상을 확인합니다.
2. Grafana를 시작합니다.
3. 아래 명령으로 Cesium 운영 콘솔을 시작합니다.

저장소 루트에서 다음 명령을 실행합니다.

```bash
cd frontend
npm install
npm run copy:data
npm run dev
```

`copy:data`는 원본을 수정하지 않고 다음 파일을 `frontend/public/data/`로 복사합니다. 데이터가 갱신되면 이 명령을 다시 실행하세요.

- `node_positions.csv`: 노드 위치와 시뮬레이션 시점
- `network_costs.csv`: 연산 노드별 경로, RTT, 도달 가능 상태와 장애 ISL
- `routing_events.csv`: 소스-목적지 경로와 라우팅 상태
- `placement_results.csv`: 시나리오별 선택 연산 노드와 배치 결과

네트워크 CSV에 정확한 슬라이더 시점이 없으면 가장 가까운 데이터 시점이 사용됩니다. 전체 링크는 CSV 경로에 실제로 등장하는 간선만 표시하며, CSV에 없는 토폴로지는 추정하지 않습니다. 화면의 토글로 전체 링크, 선택 경로, 장애 링크, 노드 라벨을 각각 켜거나 끌 수 있습니다.

## 시나리오 동기화

프런트엔드 시작 시 `http://localhost:8000/api/scenario`에서 현재 메트릭 시나리오를 읽어 선택기를 맞춥니다. 이후 시나리오를 선택하면 Cesium CSV 화면이 즉시 변경되고 같은 API로 메트릭 서버가 갱신됩니다. 우측 모니터링 패널에서 동기화 상태와 Grafana 메트릭 시나리오를 확인할 수 있습니다. 메트릭 서버가 응답하지 않아도 CSV 시각화는 계속 동작합니다.

우측 `현재 운영 상태`는 `http://localhost:8000/api/status`를 5초마다 조회한 단일 활성 스냅샷입니다. 연결이 끊기면 마지막 정상 값을 흐리게 유지하면서 경고를 표시합니다. 글로브 상단의 `시나리오 성능 비교`는 저장된 `placement_results.csv`와 `network_costs.csv`를 동시에 집계한 별도 실험 비교표입니다. `/data/workload_experiment_summary.csv`가 제공되면 저장 실험의 마감 준수율도 표시하며, 없으면 데이터 없음으로 유지합니다.

운영 상태 패널의 정상·주의·심각 배지와 경보 사유는 `/api/status`가 제공하는 결정적 운영 규칙 결과입니다. 등급이 실제로 바뀔 때만 이벤트 로그에 기록되며, 연결이 끊긴 동안에는 마지막 서버 등급을 stale 상태로 유지합니다.

연산 위성을 선택하면 `/api/nodes/{node_id}` 기반 상세·배치 작업·관련 이벤트가 노드 패널에 표시됩니다. 우측 `작업 탐색기`는 `/api/jobs`의 상태·노드 필터를, `이벤트 센터`는 `/api/events`의 등급·분류 필터를 제공합니다. API 연결이 끊겨도 마지막 정상 목록은 stale 상태로 유지되며, 하단의 작은 이벤트 로그는 기존 사용자 조작 기록용으로 계속 유지됩니다.

`인시던트 센터`는 관련 운영 이벤트를 하나의 문제로 묶어 `진행 중 → 확인됨 → 종료` 생명주기로 표시합니다. 진행 중 항목은 `확인 처리`할 수 있으며, 정상 복귀에 따른 종료는 서버의 결정적 운영 규칙이 수행합니다. 경보는 현재 조건, 이벤트는 개별 발생 기록, 인시던트는 그 기록을 묶은 운영 문제를 뜻합니다. 연결이 끊기면 마지막 인시던트 목록과 상세를 stale 상태로 유지합니다.

프로덕션 번들은 `npm run build`, 로컬 미리보기는 `npm run preview`로 실행할 수 있습니다. Cesium 정적 리소스(Workers, Assets, Widgets, ThirdParty)는 빌드 과정에서 자동 복사됩니다.

## 동적 장애 복구 표시

`/api/status`의 결정적 시뮬레이션 시각과 운영 단계가 타임라인에 표시됩니다. 장애·감지·우회·복구·정상 복원 표식은 기존 Cesium `Viewer`를 다시 만들지 않고 엔티티만 갱신합니다. 활성 장애 링크는 붉은 점선, 복구된 링크는 녹색, 재계산된 선택 경로는 노란색이며 영향 연산 노드는 사용 불가 색상으로 구분됩니다.

우측 복구 패널은 장애 시작, 감지·우회·서비스 복구 시간, 영향 작업과 장애 중 미배치 수를 표시합니다. 장애 이력은 `/api/failures`와 `/api/failures/{failure_id}`에서 가져오며 선택 시 관련 이벤트 ID와 영향 노드·작업을 보여 줍니다. API 연결이 끊기면 마지막 정상 데이터를 유지하고 stale 경고를 표시합니다.
